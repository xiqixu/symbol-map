Scene 200:40 – 01:20

Why circles, not coloured areas?

  • Choropleth: each neighbourhood gets one colour for its total. Downtown looks busiest with — records, but you can't see where inside it.
  • Big areas look important just because they are big, even when the filming happened in one corner.
  • Symbol map: every exact spot keeps its own circle. — records sit outside every neighbourhood polygon, such as the Golden Gate Bridge, and drop out of the choropleth.

Concept sketch, not in our file

// Choropleth: one colour per polygon
baseLayer.selectAll("path")
  .data(neighbourhoods)
  .attr("fill", d => color(totalIn(d)));

// Symbol map: one circle per place
symbolLayer.selectAll("circle")
  .data(locations)
  .attr("r", d => radius(d.count));

Scene 603:35 – 04:25code 05

Size by area, not by radius

A place has 4× the records. How many times bigger should the radius be?

2×. Area = πr², so to make the area 4× the radius only needs to double. The radius follows √count.

24 px

Say

  • Ask the question first, wait a moment, then reveal: 2×.
  • A = πr². If r = k·√count, then A = πk²·count, so area is proportional to count. That is d3.scaleSqrt.
  • Drag maxRadius: only the range changes; the ratios between circles stay the same. Our code uses 24.
  • Domain and range both start at 0 with no minimum radius, so the areas stay honest. We break this on purpose in Task 2.

Scene 704:25 – 05:15code 06

The data join: enter, update, exit

What .join("circle") does, written out

symbolLayer.selectAll("circle")
  .data(locations, d => d.key)  // by key
  .join(
    enter  => enter.append("circle"), // new
    update => update,                 // kept
    exit   => exit.remove()           // gone
  )
  .attr("cx", d => projection(…)[0])
  .attr("cy", d => projection(…)[1])
  .attr("r",  d => radius(d.count));
// Our file: .join("circle"), lines 124–130
enter · update · exit

We sort big → small before the join, so small circles end up on top and stay clickable.

Say

  • .data(locations, d => d.key) pairs each place with a circle. The key lets D3 recognise the same place after the data changes.
  • Pick 2015: the readout splits the circles into enter, update and exit. Then press Play.
  • Without a key, D3 matches by index, so circles would jump between unrelated places.

The area trap

What would the map look like if we had sized the circles with a linear scale?

  1. Change d3.scaleSqrt() to d3.scaleLinear().
  2. Press Run. Compare the legend on the map: 1 record vs 29.
  3. Why do most circles almost disappear?
symbol-map.js · setupSizeScale()
Edit the code, then press Run.
Why?

With a linear scale the radius grows with the count, so the area grows with count². City Hall has 29× the records of a one-record place but now gets 841× the ink. The 1,097 one-record places shrink to under a pixel.

StretchTry d3.scaleLog(). Why does it fail with a domain that starts at 0?

Done early? Bonus: pick your colours

Try one strong colour with fillOpacity: 0.15. Where circles overlap, the colour builds up into darker patches.

style.css · .symbol, .legend-symbol
Any CSS colour works: "#1d3557", "teal", "rgb(40 90 160)".

Say

  • Answer: d3.scaleLinear(). The legend's 1-record circle drops from 4.5 px to 0.8 px.
  • Ask why. Radius ∝ count means area ∝ count². 29 : 1 in the data becomes 841 : 1 on screen.
  • Stretch: log(0) = −∞, so a log scale can't include 0, and log(1) = 0 gives one-record places no size at all.

Q2Which scale makes circle area proportional to the count?

Area = πr². With r ∝ √count, area ∝ count. Domain and range both start at 0.

Q3In .data(locations, d => d.key), what does the key do?

With a key, join() knows which circles enter, update or exit when the year changes.
